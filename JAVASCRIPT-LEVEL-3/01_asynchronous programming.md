| **Feature**             | **Callback**                                                                 | **Promise**                                                                 | **Async/Await**                                                                 |
|--------------------------|------------------------------------------------------------------------------|------------------------------------------------------------------------------|---------------------------------------------------------------------------------|
| **Style**                | Function-based — a function passed as an argument to another function.       | Object-based — represents a value that may be available now or later.       | Built on top of Promises — makes async code look and behave like sync code.     |
| **Readability**          | Hard to read when nested deeply (callback hell).                            | Easier to read using `.then()` chaining.                                    | Most readable — looks like normal synchronous code.                             |
| **Error Handling**       | Must handle manually inside callback functions.                             | Uses `.catch()` for handling errors.                                        | Uses `try...catch` blocks for clean error handling.                             |
| **Used For**             | Simple async operations like event listeners or timers.                     | Managing multiple async operations with better control.                     | Writing sequential async code in a cleaner and more maintainable way.           |
| **Chaining**             | Difficult — leads to nested callbacks.                                       | Supports chaining with `.then()` for sequential execution.                  | Handled naturally with `await` — no chaining needed.                            |
| **Execution Flow**       | Executes callback after a task completes.                                   | Executes once resolved or rejected.                                         | Awaits a promise before moving to the next line.                                |
| **Error Propagation**    | Errors must be handled in each callback separately.                         | Errors can propagate through chained `.catch()` handlers.                   | Errors handled like synchronous exceptions via `try...catch`.                   |
| **Ease of Debugging**    | Hard to trace in deeply nested callbacks.                                   | Easier than callbacks but stack traces can be long.                         | Easiest to debug and maintain.                                                  |
| **Example Use Case**     | `setTimeout()`, event listeners, or simple async tasks.                     | API requests, file reading, or database queries with `.then()` chaining.    | Complex async flows like multiple API calls in sequence.                        |
